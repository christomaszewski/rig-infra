The bag player supports multiple original logger sessions on one timeline and provides offline
bag proxies for Rig's unified replay-input workflow (Rig v0.2.80 or later).

- Version-2 replay plans identify an exact list of MCAP/SQLite recording directories and a
  common timeline. One native player uses repeated `--input` arguments, received-time order,
  and one clock. Original message duplicates are retained.
- Window latch restoration, service-event inspection, call export, and coordinated type
  validation read the complete input set. Nonempty single-timestamp bags have a minimal 1 ns
  replay interval without rewriting their metadata. Version-1 plans remain supported.
- `replay-export-bags` runs a disk-backed offline merge in a locally pinned native ROS image.
  Profiles combine arrival, middleware-send, or sensor timing with `off`, `conservative`, or
  `aggressive` deduplication. Serialized payloads and original send times are preserved;
  receive/send/schedule timestamps and duplicate decisions remain in per-message provenance.
- Conservative mode preserves ambiguous ordinary messages. It removes supported identical
  service events with matching client GID, request sequence, event kind, and event timestamp.
  Aggressive mode additionally allows equal topic/type/payload matches across recordings
  within a configured receive-time window; this can remove legitimate repetitions.
- Export validates timestamp clock bounds, topic schemas, source/output integrity, and
  read-back payloads. Rig publishes immutable artifact generations and pins their identities.
  No deduplication or sensor-time sorting occurs during playback.
- The base runtime check verifies multi-input CLI support and distinct receive/send timestamp
  writing before declaring `io.rig.rosbag2.multi_input=1`.

This release also includes the source-message build improvements already on main since
v1.19.0: local checkout builds and Rig-provided Git mirror exports.

### Upgrade

Update Rig to v0.2.80 and install the v1.20.0 bag-player provider. Rebuild/publish the `fleet-ros`
base plus dependent message overlays and runtime images. The source release and public service
registry update do not rebuild deployment-specific container images. Bag export uses an
existing native image and requires valid original session indexes.

All four services in this collection share v1.20.0: `zenoh-router`, `ros2-bag-logger`,
`ros2-bag-player`, and `ros1-bag-logger`.

### Validation

Pure player, export, base contract, and cross-repository plan checks passed locally. Native
multi-input playback and bag-proxy cases are part of the required, no-skips ROS CI acceptance
gate on amd64 and arm64, covering mixed storage, duplicate preservation/removal, sensor sorting,
single-timestamp output, and provenance. No physical sensor acceptance is claimed.
