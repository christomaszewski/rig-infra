Sensor-time bag proxies schedule transforms before the sensor samples that need them, and
windowed replay restores the complete static transform set.

- Sensor profiles advance to revision 2. Dynamic `tf2_msgs/msg/TFMessage` records use their
  earliest nested transform timestamp minus `tf_lead_time_ms` (default 100 ms), clamped at zero.
  TF precedes ordinary messages at equal schedule times. The complete serialized payload is
  preserved; messages are not split and transform timestamps are not rewritten.
- Every nested dynamic transform stamp must pass the clock-domain check. Invalid sibling
  stamps cannot hide an out-of-range stamp behind fallback. Per-topic timestamp-field overrides
  for TFMessage records are rejected.
- `/tf_static` and namespaced `*/tf_static` records are preloaded before sensor data, including
  zero-stamped static transforms. Changing a child's parent or geometry during a run fails
  conversion because it cannot be safely preloaded.
- The window latch pre-pass combines the latest transform for every child frame across
  pre-window static TF messages. It preserves topic selection, remapping, and recorded
  transient-local QoS rules; ordinary latched topics still restore their last message.
- Organized PointCloud2 payloads, field offsets, point order, per-point timestamps, and padding
  remain byte-identical. Sensor scheduling changes delivery order, so snapshot triggers and
  arrival-dependent consumers can still select different data.

### Upgrade and limits

Use Rig **v0.2.81** with the **v1.20.1** player provider and a compatible native ROS image.
The source release and public service registry update do not rebuild deployment-specific
container images or baked artifacts. Existing proxies remain immutable: export the selected
sensor profile again, then prepare its recipe. Explicit proxy IDs must be changed to select
the new generation.

The TF lead is recorded time and scales with playback rate. It provides publication headroom,
not acknowledgement that a consumer has processed TF. Choose enough lead for interpolation
and delivery, use TF message filters or bounded waits, and include dynamic-TF warmup data for
windowed replay. Excessive prefetch can evict needed history from a consumer's TF cache.

Deduplication is unchanged. Conservative mode keeps ambiguous byte-identical ordinary sensor
messages. Aggressive mode can collapse likely cross-recording matches within its configured
receive-time window and can remove legitimate repeats. Original playback preserves duplicates.

All four services in this collection share v1.20.1: `zenoh-router`, `ros2-bag-logger`,
`ros2-bag-player`, and `ros1-bag-logger`.
