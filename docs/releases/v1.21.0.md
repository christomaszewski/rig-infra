## Observer

The new `observer` infra service records graph epochs and publisher/subscriber endpoints under
`graph/<name>/`, saves host inventory, settings changes and resource samples under
`system/<name>/`, and publishes `diagnostic_msgs/msg/DiagnosticArray` on `/diagnostics`.
Graph capture, system sampling, disk recording and diagnostics have separate settings. On Jetson,
the host inventory records the power profile and installed JetPack version when available.
With the metapackage absent, an exact L4T release match is marked `inferred` in both the
inventory and diagnostics.

To migrate, add `observer` to the service catalog and vehicle's `infra` list, enable it after
the recorder, and move capture settings out of the bag logger's configuration. The logger
continues to accept its old `graph` block in v1.21.0. Removing or disabling legacy capture
removes the old sidecar on the next logger startup. Existing run files remain readable.
[Observer configuration example](https://github.com/christomaszewski/rig-infra/blob/v1.21.0/observer/config/observer.example.yaml)

## Recording and export

The fleet runtime captures publisher GIDs and publication sequence numbers for supported
Lyrical Zenoh MCAP recordings. The logger uses the open run UUID as the default publication
scope. Loggers on separate hosts can use the same scope by joining the same run UUID.
Exports preserve publication identity, and conservative deduplication can use it to match
the same publication across recordings. Older bags remain readable.
[Publication identity format](https://github.com/christomaszewski/rig-infra/blob/v1.21.0/base/provenance/README.md)

This source release covers `observer`, `zenoh-router`, `ros2-bag-logger`, `ros2-bag-player`
and `ros1-bag-logger`. Rebuild the deployment's `fleet-ros` base and any dependent message
overlay to use the new recording capabilities. The release includes the base and overlay
build fixes merged after v1.20.1.
