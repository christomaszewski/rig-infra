Rig v0.2.89 version 2 recipes support `replay.export.bags.exclude` for bag proxy exports.
The list selects exact, absolute recorded ROS topic names in MCAP and SQLite inputs.

Exclusions apply before exporter type checks, payload deserialization, timestamp and TF
processing, and deduplication. Retained payloads preserve their original bytes. MCAP integrity
and publication provenance checks and SQLite metadata parsing remain active. Conversion fails
clearly when every input message is excluded.

Reports count all scanned messages in `input_messages` and provide aggregate
`excluded_messages` and `excluded_messages_by_topic` counts. Per-message provenance for retained
messages preserves original source ordinals, including gaps left by exclusions.

Upgrade to Rig v0.2.89 and refresh the player launch package:

```sh
rig swap ros2-bag-player public/ros2-bag-player@1.22.0
```

Projects using a source checkout should refresh that provider. Re-bake and redeploy artifacts
that carry the player. The updated launcher mounts its converter scripts into an existing
compatible native `fleet-ros` image or message overlay, so those images can be reused.

Re-export the recipe to create the filtered proxy, then prepare it again. Explicit proxy IDs
must select a generation with matching exclusions. All five rig-infra services share v1.22.0.
